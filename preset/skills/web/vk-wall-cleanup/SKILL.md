## When to Use
- Нужно разобрать/почистить стену ВК или удалить найденные посты.
- VK + личный Chrome пользователя, доступ к CDP :9222 с профилем google-chrome-cdp.

# VK wall cleanup via CDP

## Когда применять
Разбор/очистка стены ВК (vk.ru/wall<uid>) через личный Chrome пользователя над профилем `~/.config/google-chrome-cdp`, CDP `http://127.0.0.1:9222`. Работать ТОЛЬКО в своей вкладке (id пишем в `/tmp/vk_mytab.txt`), чужие табы не трогать.

## Подъём Chrome при падении CDP
Connection refused на :9222 → Chrome умер. НЕ изобретать команду запуска: у пользователь есть свой скрипт — `~/.hermes/scripts/server_chrome_keepalive.sh` (DISPLAY=:0, profile google-chrome-cdp, ждёт ~20-40с). Запустить его и проверить `/json/version`.

## Проверенные механики
1. **Удаление поста** — прямой переход на `https://vk.ru/wall<uid>_<pid>`: страница поста грузится быстро, кнопка «Действия» есть сразу. Прокрутка всей ленты (120 шагов scrollTo) для старых постов НЕ работает — VK их не догружает (`noload`). Всегда навигировать напрямую по адресу поста.
2. **Меню**: клик «Действия» (координаты через getBoundingClientRect, НЕ зашитые) → в дропдауне лист «Удалить» → клик. Подтверждения нет, пост исчезает.
3. **Готовность страницы поста**: `document.body.innerText.length > 350` (страница стены — >1200 + title 'записи профиля'; старая лента может залипнуть на 1361 — не ждать больше).
4. **Исключения** (не баг, закрывать как OK руками): пост с «Пост удалён» на странице — меню без «Удалить», только «Скопировать ссылку»; «автор предпочёл скрыть эту страницу»; уже удалённый пост ('Действия' не находится).
5. **Логирование**: писать результат атомарно через `os.replace(tmp)` в atexit — при kill -9/таймауте результат не теряется, но при жёстком kill между стартом и atexit запись пропадает → отмечать такие pid заново (retry), иначе «ненайденных» накапливается десятками.

## Сверка результата
Харвест (`[data-post-id]` 120 шагами) занижает/завышает счёт из-за виртуализации — НЕ сравнивать абсолютные числа «до/после» как доказательство; проверять статус каждого pid точечно (`SKIP(post-not-found)` — перепроверить вручную, не значит «удалён»).

## Приватность: смена значений дропдаунов
Открывай меню только через `el.click()` на кнопке `[data-testid="settings-privacy-open-selector-button-<key>"]` (после `scrollIntoView` + ожидание `aria-expanded=true`) — синтетические CDP mousePressed/Released не открывают меню, слушатели событий их не видят. Пункты меню ищи только внутри открытого `.vkit-t7ozZx` по точному `innerText` (в DOM/shadow/AX их нет до открытия; ищи по базовому классу без второго модификатора — он различается между ключами). Кликай пункт через `el.click()`; для direct-apply настроек значение меняется сразу, для настроек с кнопкой «Сохранить» кликай её тоже через `el.click()` внутри того же root. Верифицируй перечитыванием значения со страницы. Перед сменой дампь доступные пункты открытого меню — набор пунктов различается между ключами, несуществующий пункт никогда не «появится» повторными кликами.

## Структура файлов
- `/tmp/wall_all.json` — харвест {pid: {date, txt}}
- `/tmp/wall_todel.json` — очередь pid
- `/tmp/wall_del_done.json` — прогресс [{pid,result,t}]
- `/tmp/wall_1del.py` — один пост; `/tmp/wall_chain.py` — цепочка
