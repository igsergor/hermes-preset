# Remotion headless render from Hermes (verified 14.10.26)

## What works on this host
- Node v22, npm registry OK (`npm view remotion version` answers), ffmpeg + google-chrome present.
- `npx create-video@latest` wizard FAILS here (template clone ETIMEDOUT to github 140.82.121.10:443). Do NOT use it.
- `git clone https://github.com/remotion-dev/...` FAILS (auth prompt, no device). `git ls-remote` on some repos works. Workaround: direct `npm i` of packages + own `src/` files, no template needed.

## Working pipeline
1. `mkdir proj && cd proj && npm init -y && npm i --no-audit --no-fund remotion@<ver> react@19.1.1 react-dom@19.1.1 @remotion/bundler@<ver> @remotion/renderer@<ver>` (~5 min, run in background).
2. `src/video.tsx` exports the component (e.g. `export const Hello`). `src/Root.tsx` exports `RemotionRoot` with `<Composition id="Hello" component={Hello} .../>`. `src/index.ts`: `registerRoot(RemotionRoot)`. GOTCHA: Root.tsx must import from `./video`, NOT from `./index` — same-file import gives `component=undefined` FAIL at selectComposition.
3. `render.js` via @remotion/bundler + @remotion/renderer: `bundle({entryPoint})` (key name is `entryPoint`, not `entry`), then `selectComposition({serveUrl, id, browserExecutable:"/usr/bin/google-chrome"})`, then `renderMedia({composition, serveUrl, codec:"h264", outputLocation, browserExecutable, concurrency:2})`. Run with `node render.js` in BACKGROUND (bundle ~4-5 min, render ~1-2 min); verify with ffprobe frame count.
4. Hermes IS the AI agent from the video: user describes video -> agent writes/updates `src/*.tsx` -> runs render -> returns mp4.

## GOTCHAS that cost a failed render (all hit live, all fixed)
- **`spring()` needs `fps`.** `const {fps} = useVideoConfig()` in the component and `spring({fps, frame, from, ...})` — without fps the render dies at frame 1 with `"fps" must be a number ... to spring()`. Check every `spring()` call.
- **headless-Chrome setup timeout.** `selectComposition`/`renderMedia` default to a 30 s browser bootstrap; under load it throws `Timed out after 30000ms while setting up the headless browser`. Always pass `timeoutInMilliseconds: 180000` and `concurrency: 1` (2 concurrent tabs on 8 GB RAM doubles Chrome's slow start).
- **Never trust background notification delivery.** Poll the render log + `ps` yourself after a render finishes; the user notices a dead render long before a notification may or may not arrive. "Let me check and report back" without an actual check is a failure, not a promise.
- **Video renders with no audio by default** — Hermes delivers to Telegram as a dumb file, so a missing soundtrack is noticed instantly. See "Audio" below.
- **Verify what was rendered, not that it finished.** ffprobe the output (`codec_name=h264, nb_frames, duration`) AND look at the frames: slice 1 frame per 5 s with `ffmpeg -vf fps=1/5,scale=960:-1` and vision-analyze them — overlapping text, clipped SVG labels and off-screen elements are invisible in the log and in an ffprobe summary. A vision reply of "I can't see an image in this chat" is a TRANSIENT failure of that one call, not a clean frame — re-run vision_analyze on the same path (or a neighbouring frame) and only count the frames you actually got an answer for. Igor expects the finished, self-checked file: never deliver a render you have not looked at.
- **Curved/path text needs white stroke.** SVG `<text>` on a rainbow arc: `style={{paintOrder:"stroke", stroke:"white", strokeWidth:9, strokeLinejoin:"round"}}`. But stroke is NOT the fix for placement — a shallow rainbow arc leaves only a narrow band of arc-length, and labels spread over it (inside or outside, with or without an outward radius offset) collapse into an unreadable blob near the base and get clipped by the caption bar. Verified fix: put NO word labels on the arc at all; render a row of colour word-cards along the top of the frame (`Cards` pattern: one absolutely-positioned chip per colour, `spring({fps, frame, from: NAME_AT[en], durationInFrames: 10})` pop + `Math.pow(1 - since/26, 2)` pulse, opacity 0 before its moment). Cards stay legible at any arc geometry, and the rainbow stays clean for colour-matching.
- **Label/card timing must be driven by the SAME constants as the audio** — derive both the pulse frames and the ffmpeg cue delays from one `NAME_AT` map (`delay_ms = frame/30*1000`), otherwise the voice and the blink disagree.
- **Absolute frames everywhere is the root of "stale offset" bugs.** Every scene block, bubble `from=`, caption `to=`, `Cards from=` and even WalkSong's internal `frame - 760` base is a hardcoded frame number; inserting one scene leaves the untouched constants silently pointing at the wrong time. Define ONE `SCENES = {title: [0,150], arrive: [150,345], ...}` (plus `NAME_AT` for per-colour cues) and derive every child offset from it — the same discipline that keeps voice cues in sync. When you do move a scene, grep the file for the old number afterwards.
- **Animate entry on ONE axis only, on the element that already carries the other offset.** A wrapper with `top: 0` around a child positioned `top: 700` makes an x-axis entry (`left: base - 520*(1-p)`) read as a vertical DROP for the first frames. Put the frame-driven `top`/`left` on the same element that owns the static offset, or key the child's own offset out of the animation.
- **`Timed out after 25000 ms while trying to connect to the browser` is machine contention, not a code bug.** It appears at `selectComposition` when free RAM is under ~1 GB / load average is in double digits (ollama + gateway + the user's CDP Chrome all hold memory on this host). Check `free -m` and `uptime` FIRST; if the box is loaded, re-run the render unchanged after load drops. Never start editing the component in response to this error.
- **WATCH OUT: file writes.** The write guard refuses overwriting `render.js`/`src/*` it has not read in this session — `read_file` the target right before rewriting, or use `patch` for the one-line changes (id, outputLocation).

## Audio
- edge-tts is DEAD (403 on the Bing speech websocket, both the installed client and Hermes' TTS tool). **Working voice on this host: Google translate_tts** — `https://translate.google.com/translate_tts?ie=UTF-8&q=<urlencoded>&tl=en&client=tw-ob` with a browser `User-Agent` header (bare urllib UA is fine for this endpoint, unlike some others). One request per short line (<100 chars), mp3 out.
- Mix the whole track in ffmpeg, then mount it as ONE file. Per-clip `adelay=<ms>|<ms>` per input + `amix=inputs=N:normalize=0:dropout_transition=0`, then `alimiter=limit=0.92,loudnorm=I=-15:TP=-1.5:LRA=11`. Build a quiet music bed with `-f lavfi -i "aevalsrc='...':s=48000"` + `volume=0.55,afade=t=in/out`. Filter graphs must be written with real newlines (`\` line continuations in a script file) — a literal `\n` inside the filter string breaks parsing.
- **Stagger voice cues by MEASURED duration, never by eye.** Two lines placed 1 s apart while the first is 3.4 s long play on top of each other and the dialogue is unintelligible — this is the single most common audio defect and it is invisible in the log. After generating each mp3, `ffprobe` its `format=duration` and set each cue's delay to `previous_delay + previous_duration + 200ms`; when a scene gets longer, push its scene's `from=` frame, the bubble frame AND the composition's `durationInFrames` together.
- Confirm the mixed track is audible and not clipped with `ffmpeg -af volumedetect -f null -`: mean around −17 dB, max_volume under −3 dB (loudnorm already guarantees this).
- Mount via `public/track.m4a` + `<Audio src={staticFile("track.m4a")}/>` as the FIRST child of the root AbsoluteFill; `@remotion/media` is already installed as a dependency of `remotion`. Frame timings: convert scene frames to ms as `frame/30*1000` and round the sync by ear/frame-dump, ~0.3 s is imperceptible.
- `t` mismatch between voice and picture is caught only by watching the output — plan the audio delays from the same NAME_AT/scene constants the component uses, not by feel. `scripts/build_voice_track.py` does the whole job from a JSON cue list: fetches each line via translate_tts (cached per name), mixes with `adelay`/`amix`/`loudnorm`, adds optional sine music beds, writes the final `track.m4a`. Usage: `python3 scripts/build_voice_track.py cues.json track.m4a --music`, where each cue is `{"name":"look","text":"Look! A rainbow!","delay_ms":9000}`.
