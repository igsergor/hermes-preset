# Obsidian Vault Skill

Встроенный скилл для работы с Obsidian хранилищем (vault) на сервере.

## Конфигурация

```yaml
vault_path: "/opt/data/vault"
daily_folder: "Daily"
templates_folder: "Templates"
inbox_folder: "Inbox"
projects_folder: "Projects"
areas_folder: "Areas"
resources_folder: "Resources"
archives_folder: "Archives"
```

## Возможности

- **Создание заметок** из шаблонов (Daily, Project, Meeting, Note)
- **Поиск** по содержимому и метаданным (frontmatter)
- **Ежедневные заметки** — открытие/создание на сегодня
- **PARA структура** — Projects, Areas, Resources, Archives
- **Ссылки и бэклинки** — вики-ссылки `[[Note Name]]`
- **Теги и frontmatter** — YAML метаданные
- **Граф связей** — анализ связей между заметками

## Команды (через терминал)

```bash
# Открыть дневник сегодня
obsidian daily

# Создать заметку из шаблона
obsidian new --template Project --title "Мой проект"

# Поиск
obsidian search "тег:project AND статус:active"

# Случайная заметка
obsidian random

# Статистика vault
obsidian stats
```

## Привычка: vault-first lookup (обязательно)

**Правило:** когда задача касается того, что уже делалось на этой машине (настройки Hermes, провайдеры/модели, cron, сеть, почта и т.п.) — ПЕРЕД ответом или правкой сделать дешёвый grep по vault:

```
search_files(pattern="<2-3 ключевых слова>", path="/opt/data/vault/Resources", target="content", output_mode="files_only")
# при пустом результате — расширить на Archives/Sessions
```

1. Нашлись релевантные заметки → прочитать 1-3 самые свежие и опираться на них.
2. В ответе сослаться на заметку вики-ссылкой [[...]].
3. Ничего не нашлось → перед выводом «нет» проверить латиницу и регистр: имена каналов/авторов в vault хранятся в оригинале (`Codacus`, а не `кодакус`), поиск чувствителен к регистру — повторить запрос латиницей и через `ls | grep -i` по именам файлов, и только потом отвечать «не найдено».

**Почему:** Knowledge-заметки еженедельной дистилляции сами в контекст не попадают — без этой привычки они мёртвый груз. Пример: вопрос «почему vision падает» → grep находит `Knowledge - 2026-09-03 - Face Painting at LADA Event.md` с готовым ответом (auxiliary vision шёл на OpenRouter с нулевым балансом, 402) — верный ответ сразу, без повторных проб.

**Вопрос «есть ли в Обсидиане …» проверяется только прямым grep по vault, а не поиском по памяти.** fact_store/recall — индекс со своим ранжированием: отсутствие хита НЕ значит отсутствие заметки, ground truth — только ripgrep по файлам. Отвечать «нет» можно лишь после `search_files` с ЯВНЫМИ `path="/opt/data/vault"` и `pattern` (`output_mode="files_only"` сначала, читать контекст — только по найденным файлам). Вызов search_files без явных path/pattern молча ищет не там (текущий cwd) и может вывалить секреты из посторонних файлов в контекст.

**Когда пропускать:** заведомо новые задачи, не пересекающиеся с прошлым (новый сайт, новый сервис) — обычный workflow.

## Бэклоги идей (на будущее)

Когда пользователь просит собрать идеи на будущее («добавь в идеи …», «заметка с идеями»),
создавать ОДНУ каноническую заметку-бэклог (например `Resources/AI-LLM/Идеи … — бэклог.md`)
и при последующих запросах обновлять её (patch/write_file), а не плодить новые заметки.
Путь к канонической заметке хранить в fact_store, чтобы не потерять между тредами.
Пункты бэклога: короткое описание, зачем, сложность, зависимости, статус («на будущее»).

**При обновлении бэклога:** искать в vault связанные заметки (search_files по ключевым словам
темы) и добавлять раздел «Связанные заметки и источники» со ссылками `[[Имя заметки]]` и
кратким описанием идеи/полезности каждой. Также добавлять ссылку на источник (видео, статья,
переписка) с кратким описанием. Это помогает находить контекст при возврате к бэклогу через
месяцы.

## Синхронизация с телефоном

Доступ с телефона — через WebDAV (WsgiDAV + плагин Remotely Save), адрес `192.168.1.10`,
наружу не выставляется. Один адрес покрывает и LAN, и WG — не предлагать пользователю
несколько профилей подключения. Установка, конфиг, systemd-юнит, коды проверки, настройки
плагина и диагностика «синк без ошибок, но на телефоне пусто» — в `references/mobile-sync.md`.

**Правило диагностики мобильного синка:** если пользователь говорит «синк прошёл, но файлов
нет» — не советовать настройки плагина, а смотреть на сервере, что ПРИЕХАЛО за последние минуты
(`find /opt/data/vault -newermt '-15 minutes'`). Пустой телефонный vault при
bidirectional тихо заливается на сервер, и плагин при этом не показывает ошибок.

**Главная причина — Remote base dir, а не направление:** при пустом поле плагин берёт имя
телефонного vault как подпапку (`/vault/<Имя>`) и синхронизирует пустоту; очистка поля или «/»
не помогает — плагин всё равно считает пустое значением дефолт. Лечится переносом vault
внутрь `~/webdav-root/<Имя>` с симлинком обратно на прежний путь: подробно
в `references/mobile-sync.md`.

**Вторая причина «папки есть, файлов нет» — несовместимые имена:** если часть папок
(обычно `Resources` с YouTube-заметками) осталась пустой, а в логе плагина `FILE_NOT_CREATED`
и «too many errors», дело в символах `? " | :` в именах — Android их не создаёт, и плагин
останавливает весь батч. Проверяется скриптом `scripts/sanitize_filenames.py` (сначала
`--dry-run`), лечится переименованием + обновлением ссылок в текстах. Имена файлов в vault
должны оставаться Android-совместимыми: любые скрипты, создающие заметки из заголовков
видео, обязаны санировать `? : " |` до записи на диск.

## Дедупликация: сверять по Video ID, а не по именам

Скрипты, создающие заметки из внешних источников (лайки, очереди, бэкфиллы), обязаны перед созданием сверять канонический внешний ID (`watch?v=`) со всем каталогом — совпадение имён файлов недостаточно, потому что старые и новые заметки называют один и тот же ролик по-разному. Иначе каждый прогон плодит дубли-заглушки рядом с уже изученными заметками. Аудит: собрать `videoId → [файлы]` по первым ~1500 символам каждой заметки; при слиянии побеждает заметка с реальным содержанием, из проигравшей переносятся недостающие frontmatter-поля (`liked_at`, `duration`, `views`), затем она уходит в корзину, а не удаляется.

Скилл загружается автоматически при упоминании Obsidian, vault, заметок, PARA, Zettelkasten.
Предоставляет функции для delegate_task суб-агентов для массовой обработки заметок.

## Раскладка Resources (согласована, переупорядочичивание не предлагать)

Корень `Resources/` держит хабы и сырьё (json/csv), всё остальное разложено по темам:

```
Resources/
├── Knowledge/<AI-LLM|Hermes|Mail|Infra-Shopping|Finance|Misc>/   # дистилляты сессий
├── YouTube/AI/                                                   # ценное (агенты, локальные LLM, кодинг)
├── YouTube/Archive/                                              # bulk старых лайков
├── AI-LLM/                                                       # ключи, модели, обзоры провайдеров
├── Dev-Tech/                                                     # команды, Docker, VPN, репозитории, контакты
├── Home-Finance/                                                 # бюджет, подписки, книги
├── Documents/
├── Resources Hub.md                                              # карта разделов
└── export_*.json / *.csv                                         # сырьё для автосбора корзины
```

- Подпапка Knowledge выбирается маппингом тегов (`knowledge_subdir()` / `TAG_SUBDIR`) в пайплайне памяти — несовпавший тег → `Misc`. Новые YouTube-заметки лайк-крона → `YouTube/Archive/`; ветвь шаблона `knowledge` в `obsidian-cli.py` пишет в `Knowledge/Misc/`.
- Вики-ссылки резолвятся по имени, поэтому переезд их не рвёт — в хабах писать `[[Имя заметки]]`, БЕЗ путей.
- ⚠️ Любой новый читатель/писатель vault-файлов обязан идти рекурсивно (`rglob`): нерекурсивный обход `Resources` молча теряет всё, что лежит в подпапках.
- Санитизировать имена при создании (`/ \ : * ? " < > |`): не только мобильный синк, но и запись на диск падает на слэше в заголовке.

Правила реорганизации, ремап путей в `vault_vectors.db` без переэмбеддинга и порядок
перепроверки после переезда — в скилле `hermes-memory-providers` (секция про переезд).
